## 1. 開会前チェックリスト

開場の **30 分前** までに全項目を確認してください。

### システム確認（全体管理者が実施）

- [ ] 本番 URL にアクセスし、トップ画面が表示される
  - 来場者 URL: `https://reception-frontend-686429613269.asia-northeast1.run.app`
- [ ] 全体管理者でログインできる（`/admin` ページ）
- [ ] 全ブースが登録されており、設定値（時間・人数・体験タイプ）が正しい
- [ ] 全ブースの `整理券発行: 有効` になっている（is_accepting = true）
- [ ] 通知テンプレートの文面が正しい（ブース名・場所に誤字がない）
- [ ] リスク説明文の内容が最新版である
- [ ] 紙の同意書（7〜9 歳用）が印刷されており、管理番号（P-0001〜）が振られている

### 端末・機材確認（各ブース担当スタッフが実施）

- [ ] タブレット / スマホの充電が十分にある（80%以上推奨）
- [ ] Wi-Fi または通信に問題がない（来場者 URL にアクセスして確認）
- [ ] カメラアプリが起動し、QR コードを読み取れる
- [ ] 担当ブースのパスワードを把握している
- [ ] ブース運用画面にログインできる

### 紙バックアップの用意（全体管理者が準備）

- [ ] 手書き整理券用の用紙・ペンを各ブースに配布
- [ ] 受付番号が分からなくなった来場者向けの本人確認シート（受付番号一覧の印刷）

## 2. 来場者の受付フロー

来場者は**自分のスマホ**から操作します。スタッフが代わりに操作する必要はありません。

```
来場者が URL にアクセス
  ↓
ニックネーム + 4桁 PIN を入力して受付登録
  ↓
受付番号（例: A-105）と QR コードが表示される
  ↓
「必ずスクショしてください」の画面 → スクショを促す
  ↓
通知許可の案内（任意）→ スキップしても OK
  ↓
マイページへ → 各ブースの整理券を取得
```

### 来場者に伝えること

- **スクショは必須ではないが強く推奨**（ブラウザを閉じても再ログインできる）
- 再ログインは「受付番号 + PIN」で可能
- 通知を有効にすると呼び出し時にスマホに通知が届く

## 3. 年齢別の対応フロー

HMD 体験には年齢制限があります。来場者が整理券を取得する際、年齢入力があります。

| 年齢 | 対応 |
|---|---|
| **7 歳未満** | システムが自動で受付拒否。「体験できません」のメッセージが表示される |
| **7〜9 歳** | オンライン取得不可。システムが「スタッフへお越しください」と案内する。**ブース担当スタッフが手動発行** |
| **10〜12 歳** | 保護者同意フォームが表示される。保護者がスマホ上でリスク説明文を読んで同意する |
| **13 歳以上** | 通常フローで取得可能 |

### 7〜9 歳の手動発行手順（ブース担当スタッフが対応）

1. 保護者と子どもがブースに来たら「特殊フロー手動発行」ボタンを押す
2. 紙の同意書（P-XXXX の管理番号入り）を保護者に渡し、記入してもらう
3. タブレットで以下を入力する：
   - 来場者の受付番号（QR スキャン or 手入力）
   - 体験人数・各参加者の年齢と氏名
   - 保護者氏名・紙の管理番号（P-XXXX）
4. タブレット画面のリスク説明文を保護者に読んでもらう
5. 保護者が「同意」ボタンを押す
6. 整理券を発行する
7. 紙の同意書を回収して保管する（別途、保管場所を運営側で決定）

## 4. スタッフのログイン方法

### ブース担当スタッフ

1. 来場者 URL と同じページを開く
2. 右上（またはメニュー）から「スタッフログイン」を選択
3. 担当ブースを選択する
4. そのブースの共有パスワードを入力する
5. ブース運用画面が開く

> パスワードが分からない場合は全体管理者に確認してください。

### 全体管理者

1. `/admin/global/login` にアクセス
2. 管理者 ID とパスワードを入力する

## 5. ブース運用画面の使い方

ログイン後に表示される画面。タブレットを横向きにして使うと見やすいです。

### 画面の見方

```
[優先呼び出し]  ← pending から戻ってきた来場者（最優先で処理）
  - T-105 ○○さん（戻ってきました）

[呼び出し中]
  - T-103 △△さん（3人）

[待機中] × 5

[保留中(pending)] × 2
```

### 主な操作

| 操作 | ボタン | タイミング |
|---|---|---|
| 整理券を呼び出す | 「先頭を呼び出す」または「N件呼び出す」 | 体験が終わって次の人を呼ぶとき |
| QR スキャンで入場処理 | 「QRスキャン」 | 来場者が来たとき（基本操作） |
| 手動で入場処理 | 「手動入場処理」→受付番号入力 | QR が読めないとき |
| キャンセル | 各行の「キャンセル」 | 来場者が辞退したとき |

### 呼び出しのタイミング目安

- `call_threshold`（ブース設定値）を参考に、体験スペースが空いたら呼び出す
- 一度に呼びすぎると、来場者が集まりすぎるので注意

## 6. QR スキャンによる入場処理

来場者がブースに来たら QR コードをスキャンします。

### スキャン結果と対応

| 結果（画面表示） | 意味 | スタッフの対応 |
|---|---|---|
| **「入場処理が完了しました」（緑）** | 正常に入場処理できた | 体験を案内する |
| **「優先呼び出しに戻しました」（黄）** | 保留中だった来場者が戻ってきた | 「もう少しお待ちください」と伝え、次の空きで優先案内する |
| **「呼び出し前ですが入場処理しますか？」** | まだ呼び出していない状態でスキャンした | 確認して、体験させる場合は「はい」を押す |
| **「既に入場済みです」（グレー）** | 二重スキャン | そのまま通す（再チェック不要） |
| **「このブースの整理券が見つかりません」（赤）** | 別ブースの QR または無効な QR | 来場者の受付番号を確認し、手動処理へ |

### 保留中（pending）の来場者が戻ってきた場合

1. スキャンすると「優先呼び出しに戻しました」と表示される
2. 予約一覧の **「優先呼び出し」セクション** に移動する
3. 体験中の人が終わったら、再度 QR をスキャンして入場処理する（2回スキャンする運用）

## 7. マッチメイキング型ブースの操作

5 人対戦ゲームなど、複数グループを結合して開催するブース固有の操作です。

### 画面の見方（マッチ待機列ビュー）

```
[マッチ待機 (public)]  累積人数: 3 / 5
  - T-103 山田家（3人）14:23
  - T-105 ソロ（1人）14:25
  → あと 2 人で自動開催

[マッチ待機 (private)]
  - T-101 鈴木家（4人）[呼び出しボタン]

[体験中]
  - セッション #45（5人、14:40 終了見込み）
```

### public モード（マッチメイキング）

- 累積人数が `target_party_size`（例: 5 人）に達すると**自動的に全員が呼び出される**
- 待ち時間が長くなりそうなら「強制開催」ボタンで `min_party_size` 以上なら開催できる

### private モード（プライベートマッチ）

- 「呼び出しボタン」を手動で押す（自動では呼び出されない）
- グループのメンバーが全員揃っているか確認してから押す

### 強制開催の手順

1. 「強制開催」ボタンを押す
2. 「現在 X 人で開催します。よろしいですか?」の確認が出る
3. 「はい」を押すと、待機中の全 public 整理券が呼び出される

## 8. よくあるトラブルと対処法

### 来場者が「QR コードを忘れた / スクショを撮っていない」

**対処**: 受付番号を確認して手動入場処理する。

1. 「手動入場処理」ボタンを押す
2. 来場者の受付番号（例: A-105）を入力する
3. 正しければ入場処理される

受付番号も分からない場合は、全体管理者に来場者一覧から名前で探してもらう。

---

### 来場者が「ブラウザを閉じて受付番号が分からなくなった」

**対処**: 本人に再ログインしてもらう。

1. 来場者 URL にアクセス
2. 「再ログイン」を選択
3. 受付番号 + PIN を入力

受付番号も PIN も忘れた場合 → 全体管理者に問い合わせ（来場者一覧から探す）。

---

### スタッフのタブレットが固まった / 画面が更新されない

**対処**: ブラウザをリロード（F5 または引っ張って更新）してから再ログインする。

---

### 通知が来場者に届かない

**対処**: 画面 polling（自動更新）で代替されるので、**来場者に「画面を開いたままにしてください」と伝える**。  
通知が届かなくても、画面を開いていれば呼び出し状態に切り替わる。

iOS（iPhone）は Safari から直接通知を受け取れない仕様のため、画面 polling が主な手段。

---

### 「このブースは現在整理券の発行を停止しています」と表示される

**対処**: 全体管理者がブース設定の `整理券発行` を「有効」に切り替える。  
（長い待ち行列を制御したいときに意図的に停止することもある）

---

### 来場者が呼び出し後に現れず、pending になってしまった

**対処**: 来場者が戻ってきたら QR をスキャンして優先呼び出しに戻す（Section 6 参照）。  
戻ってこない場合は、スタッフ判断でキャンセルする。

---

### システムが全く使えない（全停止）

**対処**: 紙の整理券に切り替える。

1. 各ブースに配布している手書き用紙で整理券番号を発行
2. 呼び出しは口頭またはアナウンスで行う
3. 全体管理者に障害状況を報告する
4. 復旧後、紙で入場処理した分は手動でシステムに反映する

---

## 9. 閉会後の手順

### ブース担当スタッフ

- [ ] 残っている `waiting` / `called` / `pending` の整理券をすべてキャンセルする（「運営キャンセル」）
- [ ] 紙の同意書（7〜9 歳分）が回収されているか確認する
- [ ] タブレットからログアウトする

### 全体管理者

- [ ] 全ブースの `整理券発行` を「停止」に切り替える（新規取得を締め切る）
- [ ] 必要なデータを CSV エクスポートする（来場者一覧・整理券一覧・ブース別集計）
- [ ] 通知テンプレートや設定に変更があれば記録しておく
- [ ] 紙の同意書を所定の場所に保管する
