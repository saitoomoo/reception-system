# 機能: 馬レース応援（Cheer）

整理券を取得せず「観客」として馬レースブースに参加する機能。レース中の馬にニンジンを投票し、推し馬を応援できる。

---

## 1. 機能概要

馬レースブース（`experience_type = sequential`）固有のオプション機能。HMD を装着して実際に馬に乗る来場者とは別に、整理券を持たない観客がブース外からスマホで参加できる仕組み。来場者がニンジンを投票した馬ほどレース内で有利になる（またはその演出を行う）。

---

## 2. ユーザーストーリー

- 来場者として、馬レースを体験しない（整理券を持たない）場合でも、応援という形でイベントに参加したい
- 来場者として、5頭の馬から1頭を選んで、ニンジンボタンを連打して応援したい
- 来場者として、自分のニンジン投票数がレースに反映されることを楽しみたい
- ブース担当スタッフとして、現在の馬ごとのニンジン投票数をレース演出に使いたい

---

## 3. 画面構成

### 3-1. 応援入口

ブース詳細画面（`booth-detail`）の「応援で参加」セクション（アコーディオン）から遷移する。馬レースブースのみ表示。

### 3-2. 応援画面

- **馬の選択**: 5頭の馬をカードリストで表示。1頭のみ選択可能
- **ニンジンボタン**: 選択した馬が決まると表示。タップするたびにニンジン数が加算される
- **ニンジンカウント**: 自分が与えたニンジン数をリアルタイム表示

#### 馬のデータ（固定または管理者設定）

| 馬番 | 馬名 | カラー |
|---|---|---|
| 1 | サンダーボルト | 赤 |
| 2 | ブルースカイ | 青 |
| 3 | ゴールデンスター | 黄 |
| 4 | エメラルドウィンド | 緑 |
| 5 | ミッドナイトシャドウ | 紫 |

## 4. 業務ルール

### C-001: 整理券不要

- この機能は整理券（Ticket）とは独立している
- 来場者登録（Visitor）も不要にするか必要にするかは未決定（→ §8 未決定事項参照）

### C-002: 馬は1頭のみ選択

- 選択後の変更は可能とする（別の馬を選ぶと切り替わる）

### C-003: ニンジンの投票はリアルタイムで集計

- タップのたびにサーバーへ送信するか、一定間隔でバッチ送信するかは実装時に決める
- レース演出との連携方式は運営マニュアル側で定義する

### C-004: 投票期間

- 馬レースブースの `open_at` 〜 `close_at` の間のみ投票可能
- レース中以外の投票データの扱いは未決定

---

## 5. サーバー側の処理

### `VoteCarrot`（CheerService）

入力:
- horse_id（1〜5）
- count（今回タップ分のニンジン数）
- visitor_id（任意。未ログイン来場者を許容する場合は不要）

処理:
1. horse_id の存在確認
2. ニンジン数を該当馬の集計に加算

出力:
- total_carrots（その馬の現在のニンジン総数）

### `GetCheerStatus`（CheerService）

スタッフまたは来場者が馬ごとのニンジン数を確認するためのエンドポイント。

入力:
- booth_id

出力:
- 馬ごとの集計（horse_id, total_carrots）

---

## 6. データモデル

既存テーブルとの関係を最小限にするため、専用テーブルを追加する。

### `cheer_votes`（案）

| カラム | 型 | 備考 |
|---|---|---|
| id | bigserial PK | |
| booth_id | bigint FK | 馬レースブース |
| horse_id | int | 1〜5 |
| visitor_id | bigint FK nullable | 未ログイン許容の場合は NULL |
| carrot_count | int | |
| created_at | timestamptz | |

集計は `SUM(carrot_count) GROUP BY horse_id` で行う。

---

## 7. 非機能要件・スケール

- ニンジンボタンの連打が想定されるため、クライアント側でデバウンス（例: 1秒ごとにまとめて送信）を設ける
- 1,000人が同時にタップしても耐えられる書き込み性能が必要
- 集計クエリは読み取りキャッシュで対応（数秒の遅延を許容）

---

## 8. 未決定事項

- **来場者登録（Visitor）が必要か**: 匿名投票を許容するか、受付済み来場者のみ投票可能にするか
- **ニンジン数のレースへの反映方法**: 演出上の反映（アニメーション等）なのか、ゲームロジックへの反映なのか。ブース担当スタッフとの連携方式
- **1人あたりの投票上限**: 無制限か上限を設けるか
- **馬のデータ管理**: ハードコードか管理画面で設定可能にするか
- **投票期間の制御**: レース単位（セッション単位）でリセットするか、1日通算で集計するか
- **`GetCheerStatus` の公開範囲**: 来場者にも見せるか（投票ランキング表示）、スタッフのみか
